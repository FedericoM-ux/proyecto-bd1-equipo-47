\# Optimización de Consultas a través de Índices

 \#\# 1\. Definición y Objetivo \* \*\*Definición:\*\* Los índices son estructuras B-Tree (árboles balanceados) que el motor de SQL Server utiliza para localizar información de forma más eficiente. Funcionan de forma análoga al índice de un libro, evitando recorrer todas las páginas (filas) de una tabla para encontrar un registro

. \* \*\*Objetivo:\*\* Reducir significativamente la cantidad de lecturas lógicas (I/O) y los tiempos de CPU en consultas sobre tablas de gran volumen del Sistema de Hamburguesería (como el historial de pedidos), mejorando la velocidad de respuesta y la escalabilidad del sistema.

\--- \#\# 2\. Ventajas y Aplicaciones \* \*\*Reducción de Lecturas Lógicas:\*\* Disminuye el número de páginas de disco analizadas durante la ejecución de las consultas. \* \*\*Optimización de Filtros y Rangos:\*\* Mejora el rendimiento en búsquedas por rangos de fechas, clientes, productos y categorías. \* \*\*Índices de Cobertura (\`INCLUDE\`):\*\* Permiten resolver consultas completas desde el propio índice sin necesidad de acceder a la tabla base (\*Key Lookup\*). \* \*\*Escalabilidad:\*\* Permite mantener tiempos de respuesta bajos a medida que aumenta la cantidad de pedidos históricos en la base de datos. 

\--- \#\# 3\. Caso Concreto Aplicado al Sistema de Hamburguesería En el sistema de la hamburguesería, la administración realiza análisis frecuentes sobre las ventas registradas durante determinados períodos de tiempo. \* \*\*Tabla analizada:\*\* \`dbo.Pedido\` (o tabla de prueba histórica \`dbo.VentaHistorica\` poblada masivamente para la demo). \* \*\*Escenario de negocio:\*\* Filtrado del total de ventas y pedidos entre un rango de fechas específico (\`fecha BETWEEN '2026-01-01' AND '2026-03-31'\`). \* \*\*Prueba comparativa:\*\*

 Se evalúa la consulta en tres escenarios clave:   
1\. Consulta sin índices (\*Table Scan\*).  
 2\. Consulta con índice sobre la columna \`fecha\` (\*Index Seek\* \+ acceso a tabla).  
 3\. Consulta con índice de cobertura (\`INCLUDE(total, id\_cliente)\`).

Implementación en SQL Server Express \`\`\`sql USE PedidosRestaurant; GO \-- \========================================================================= \-- PARTE 1: CREACIÓN DE TABLA HISTÓRICA Y CARGA MASIVA DE PRUEBA (100.000+ REGS) \-- \========================================================================= IF OBJECT\_ID('dbo.VentaHistorica', 'U') IS NOT NULL DROP TABLE dbo.VentaHistorica; GO CREATE TABLE dbo.VentaHistorica ( id\_venta BIGINT IDENTITY(1,1) PRIMARY KEY, fecha\_venta DATE NOT NULL, importe DECIMAL(12,2) NOT NULL, id\_cliente INT NOT NULL ); GO \-- Poblado de datos masivos simulados para generar impacto en el plan de ejecución SET NOCOUNT ON; WITH Numeros AS ( SELECT TOP (100000) ROW\_NUMBER() OVER(ORDER BY (SELECT NULL)) AS n FROM sys.objects a CROSS JOIN sys.objects b CROSS JOIN sys.objects c ) INSERT INTO dbo.VentaHistorica (fecha\_venta, importe, id\_cliente) SELECT DATEADD(DAY, ABS(CHECKSUM(NEWID())) % 365, '2026-01-01'), ROUND(RAND(CHECKSUM(NEWID())) \* 15000 \+ 1000, 2), ABS(CHECKSUM(NEWID())) % 50 \+ 1 FROM Numeros; GO \-- \========================================================================= \-- PARTE 2: ESCENARIOS DE ÍNDICES \-- \========================================================================= \-- Escenario 2: Crear índice simple sobre la fecha \-- CREATE NONCLUSTERED INDEX IX\_VentaHistorica\_Fecha ON dbo.VentaHistorica (fecha\_venta); \-- Escenario 3: Crear índice con cobertura (INCLUDE) \-- CREATE NONCLUSTERED INDEX IX\_VentaHistorica\_Fecha\_Cobertura ON dbo.VentaHistorica (fecha\_venta) INCLUDE (importe, id\_cliente);
